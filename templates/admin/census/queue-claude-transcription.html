What will happen

  1. Only selected schedules with an original image are eligible. {% if ineligible_count %}{{ ineligible_count }} selected schedule{{ ineligible_count|pluralize }} will be skipped.{% endif %}
  2. Limit caps the number of eligible schedules queued as individual jobs, ordered by the schedule’s internal database ID. If fewer than the limit are eligible, only that smaller number is queued. The deployment hard maximum is {{ max_run_limit }} jobs per run.
  3. The worker groups those jobs into provider batches of up to {{ batch_size }} requests, subject to the encoded-size safety limit. One run may therefore create several provider batches.
  4. {{ max_tokens|intcomma }} max output tokens is applied to each schedule. It limits generated response length; it is not an input limit, a predicted usage amount, or a spending cap.
  5. The run key, model, prompt/schema contract, application revision, and pricing below become immutable provenance. Results remain comparison candidates and never overwrite canonical census data automatically.
