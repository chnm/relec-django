What will happen

  1. Every ready selected schedule is queued under the single run key above. {% if missing_image_count %}{{ missing_image_count }} without an original image will be skipped.{% endif %} {% if active_work_count %}{{ active_work_count }} with already queued or active work will be skipped.{% endif %}
  2. Leave Pilot size blank for the complete ready selection. Enter a number only when you intentionally want a smaller trial, chosen in internal record-ID order. Successfully transcribed schedules may be queued again in a new run; only active work is excluded.
  3. The worker groups those jobs into provider batches of up to {{ batch_size }} requests, subject to the encoded-size safety limit. All of those batches still belong to this one named run. The emergency ceiling is {{ max_run_jobs|intcomma }} jobs per run.
  4. {{ max_tokens|intcomma }} max output tokens is applied to each schedule. It limits generated response length; it is not an input limit, a predicted usage amount, or a spending cap. Claude Sonnet 5 adaptive thinking is disabled so this budget remains available for the structured transcription; that behavior is frozen with the run.
  5. The run key, model, prompt/schema contract, application revision, and pricing below become immutable provenance. Results remain comparison candidates and never overwrite canonical census data automatically.
